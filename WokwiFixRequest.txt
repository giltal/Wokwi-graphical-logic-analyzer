attrs schema in chip.json — let a chip declare { "id": "triggerMode", "type": "enum", "options": [...] , "default": 0 } and have the editor render the same property panel it gives built-in parts, writing into diagram.json. This is the cleaner one: it is design-time, matches existing behaviour, needs no new runtime API, and would also fix the "sliders only" limitation for chips.
attrWrite(attr_id, value) runtime import — lets the chip push its live state back into the part's attrs. More powerful (a chip could save any computed state), but it mutates the project from the simulation, which they may not want.
